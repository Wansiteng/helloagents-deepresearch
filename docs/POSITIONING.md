# 项目定位 (Positioning)

> 本文是项目的「宪法」。新增任何特性、砍任何特性，都先回到这份文档检查是否符合定位。如果一个想法跟这份文档冲突，要么修改文档（很慎重），要么放弃想法。

---

## 一句话定义

**一个完全本地运行、能深度阅读你私人知识库的研究助手。**

---

## 立意演化

项目最初的目标是「找工作时有一个 agent 相关作品集」。这个目标已达成，但市面上已经有 ChatGPT Deep Research、Claude Research、Perplexity Pro、Grok DeepSearch 等成熟产品，模型能力、抓取能力、引用质量都不可能赢。继续做一个「通用深度研究助手」是没有产品意义的。

经过反思，项目的存在价值不在于「做得更好的通用研究」，而在于**做巨头结构性做不到的事情**。

---

## 我们不做什么（先于「我们做什么」）

把放弃写在前面，是为了挡住未来「也加上 X 吧」的诱惑。

- ❌ **不追求通用 web 研究的"广度"或"质量"**——这条赛道已经被 ChatGPT/Claude 占据，模型差距是结构性的
- ❌ **不强制云端 LLM**——本地始终是默认值与一等公民；云端是用户**显式 opt-in** 的高级选项（见「我们做什么」第 1 条）
- ❌ **不做"AI 助手"或"对话机器人"**——只做研究这一件事
- ❌ **不追求中文/英文以外的多语种支持**——精力有限，先把核心做好
- ❌ **不追求美观度超过功能的 UI**——MVP 阶段功能优先

---

## 我们做什么

### 1. 隐私优先 (Privacy-first by default, cloud opt-in)

**默认行为**：所有计算在本机完成。

- LLM 推理默认走本地：Ollama / LM Studio / mlx-lm
- 向量化、检索、笔记持久化**始终**在本机（这一条不退让）
- 默认离线可工作；联网搜索是**可选增强**而非依赖
- 出站流量可显式审计（一个端点就能 grep）

**云端 LLM 是显式 opt-in**：用户可以在配置里填写自己的 API（OpenAI / Anthropic / DeepSeek / Moonshot / 自托管 OpenAI 兼容端点等）：

- 切到云端必须是**用户主动行为**——填 API key、改 provider，UI 应有"数据将出本机"的明确提示
- 即使 LLM 走云端，**索引层与笔记层始终本地**——你的 Obsidian/PDF 内容不被云端供应商持久化（仅在请求中临时上下文）
- 适合的场景："我有 GPT-4 订阅，我愿意用它读我的 vault；我相信 OpenAI 的 zero-retention API"
- 不适合："我研究的内容绝对不能出本机"——这种就关掉云端、用 Ollama

**为什么允许云端**：本地模型在 2026 年仍然达不到 GPT-4 / Claude 4.x 级别的推理质量。强制本地等于把"质量优先"用户挡在外面。给用户选择权，让 ta 自己平衡隐私 vs 质量，比我们替 ta 做决定更对。

**适合本地模式的研究主题**（举三个真实例子，不靠形容词）：

| 场景 | 为什么云端工具不合适 |
|---|---|
| 「翻译我的劳动合同里这条竞业条款」 | 合同是个人敏感信息，不应该出现在 OpenAI 训练集里 |
| 「研究一下我做的这个心电图报告里的异常项」 | 医疗信息，HIPAA / 国内个保法都很敏感 |
| 「整理我们公司内部 wiki 里关于 X 系统的所有文档」 | 公司禁止把内部资料喂给 ChatGPT |

### 2. 个人知识库整合 (Personal knowledge integration)

**第一公民数据源**：本地文件系统

- Obsidian vault（与 [Wansiteng/obsidian-local-ai-agent](https://github.com/Wansiteng/obsidian-local-ai-agent) 项目在数据层共享）
- 本地 PDF 文件夹
- 本地代码仓库
- Zotero 库

网络搜索是**补充信号**，不是核心。研究产出反哺知识库：报告 → Markdown → Obsidian。

> 关键定位：跟巨头的差异不是「我们也做 web research」，而是「我们的第一公民数据源是你的本机数据」。

### 3. 可干预 (Steerable)

- 用户可中途**编辑任务计划**（PlannerAgent 输出后用户能改）
- 用户可中途**否决子任务**或**追加澄清**
- 长跑研究（>10 分钟）必须可中断、可恢复
- 研究状态可序列化，下次能续跑

商业工具是「submit and wait」的黑盒；本项目要做白盒、可干预的体验。

## 目标用户画像

### Primary user (first user = 我自己)

- **画像**：隐私敏感的技术工作者，重度 Obsidian 用户
- **使用场景**：技术调研、个人文档整理、敏感主题研究
- **能容忍**：稍慢、稍丑、需要本地配置 LLM

### 类似画像（Secondary）

- 研究生 / 独立研究者：长跑、重隐私、个人笔记重
- 律师 / 医生 / 企业内部研究人员：信息合规要求高
- 科研工作者：跨论文 / 跨数据集的深度阅读

### 明确不是

- 普通消费者（要的是开箱即用的"AI 助手"）
- 非技术用户（不会装 Ollama、不会改 .env）
- 一次性查询用户（直接用 ChatGPT 反而更快）

## 与既有方案的对比

承认弱项才有可信度。本项目的强项与弱项是结构性的，不是因为投入不够。

| 维度 | ChatGPT Deep Research | Claude Research | Perplexity Pro | 本项目 |
|---|---|---|---|---|
| 数据出本机（默认） | 是 | 是 | 是 | **否** |
| 数据出本机（用户切云端 LLM 后） | — | — | — | LLM 请求出，索引/笔记仍在本地 |
| 接入个人 Obsidian | ❌ | ❌ | ❌ | **✅ 规划中** |
| 接入本地 PDF 库 | ❌ | ❌ | ❌ | **✅ 规划中** |
| 接入私有代码仓 | ❌ | ❌ | ❌ | **✅ 规划中** |
| 中途可干预 | ❌ | ❌ | ❌ | **✅ 规划中** |
| LLM 推理质量 | ★★★★★ | ★★★★★ | ★★★★ | ★★ ~ ★★★（本地）/ ★★★★★（云端 opt-in）|
| 通用 web 检索质量 | ★★★★★ | ★★★★★ | ★★★★★ | ★★ |
| 引用准确度 | ★★★★ | ★★★★★ | ★★★★ | ★★ |
| 单次成本 | 订阅 ~$20/mo | 订阅 ~$20/mo | 订阅 ~$20/mo | **0**（本地）/ 按 API 量计费（云端）|
| 上手门槛 | 低 | 低 | 低 | 高 |

**关键洞见**：右边四列里有三个是结构性优势（数据出本机、个人知识库、可干预），其他维度商业工具更强。我们的产品价值不在于做得更全面，而在于这三件事别人做不到。

## 决策框架（New Feature Filter）

新增任何特性时，按顺序问以下问题。**任何一题答 No 都应严肃考虑放弃**：

1. 这个特性是否服务于「隐私 × 个人知识库 × 可干预」三个核心？
2. 如果用 ChatGPT/Claude/Perplexity 能做且做得更好，那本项目做这个的差异化在哪？
3. 这个特性是否要求用户额外配置云端服务 / 注册账号 / 暴露隐私？
4. 这个特性是否会让"目标用户画像"之外的用户群也想用？（如果是，应该警惕——可能在偏离定位）

## 一些反例（不该做的事，举例提醒）

- ❌ 「加一个聊天对话框，让用户可以在任意时刻问 AI 任何问题」——偏离「只做研究」
- ❌ 「**默认**用云端 LLM、本地变成 opt-in」——颠倒了「本地默认 + 云端 opt-in」的关系
- ❌ 「提供托管的云端版本，让用户不用本地装」——本项目的部署形态始终是用户本机；不做 SaaS
- ❌ 「把用户的 Obsidian/PDF 内容上传到我们的服务器做集中索引」——索引层永远本地，无论 LLM 是否云端
- ❌ 「加上多模态：上传图片让 AI 分析」——偏离核心
- ❌ 「做一个 Chrome 插件，在网页上随时调研究」——偏离用户画像

> 关键区分：**用户自带云端 API key** 跟 **我们提供云端服务** 是两件事。前者允许（隐私是用户知情的选择），后者不做（我们不存任何用户数据）。

## 复盘问

1. 过去三个月新增的特性，符合定位吗？哪些越界了？
